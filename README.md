# PIXEL KITCHEN — 픽셀 복원 실험실

> 배포 단계 안내(2026-10-09): 로컬 검토 후 사용자의 공개 배포 승인을 받았습니다. 아래 LOCAL ONLY/NOT_RUN은 배포 전 검토 기록입니다. 승인 후 실제 공개 결과는 [통합 배포 검증](https://github.com/HyungminYoon1/web-lab/blob/main/docs/verification.md)의 최신 배포 절에서 따로 확인합니다.

목표 이미지의 처리 과정을 추론하고, 실제 픽셀 계산으로 가설을 확인하는 브라우저 실험실입니다. 이번 확장은 **로컬 구현**이며 커밋·푸시·배포하지 않았습니다. [기존 공개 페이지](https://hyungminyoon1.github.io/pixel-kitchen/)는 이번 코드의 검증 증거가 아닙니다.

## 복원 과제 / 자유 처리 실험실

- 시드로 재현하는 합성 장면과 목표: 밝기 이동 → 평균 커널 → 방향 Sobel → 문턱값 순서 → 네 단계 경계 지도, 총 5단계.
- 과제에서는 프리셋을 숨깁니다. 허용 연산·평균 계수 조건·단계 수·MAE/RMSE 기준을 함께 만족해야 다음 단계가 열립니다. 단서는 평탄부, 점 퍼짐, 경계 부호, 중간 회색을 읽도록 안내합니다.
- 자유 실험은 3×3 커널, Sobel X/Y/크기, 문턱값을 최대 4단계로 연결합니다. 추가·삭제·순서 변경, 직접 계수 편집과 계수 합 정규화를 지원합니다.
- 목표와 최종 결과의 실제 MAE, RMSE, 최대 RGB 차이, 부호 평균, 알파 MAE와 차이 지도를 계산합니다. 이전 시도와 오차가 개선됐는지도 표시합니다.
- 원본/목표 ↔ 중간 단계/최종 결과의 좌우 와이프, 각 단계 입력을 사용하는 9픽셀 계산 검사, 방향키 픽셀 이동.
- PNG·JPEG·WebP 로컬 가져오기, 계산/읽기 취소, 샘플 복원, 최종 PNG 다운로드. 가져온 개인 사진에는 복원 과제 점수를 부여하지 않습니다.

시드는 입력 후 `시드로 처음부터`로 적용합니다. 새 시드는 진행을 초기화합니다. 자유 실험과 진행 상태는 페이지 메모리에만 있으며 새로고침/페이지 종료 시 사라집니다. 정답 파이프라인은 정적 소스에서 읽을 수 있습니다. 학습용 과제이며 경쟁용 부정행위 방지 시스템은 아닙니다. 같은 목표를 만드는 다른 허용 파이프라인도 통과할 수 있습니다.

다른 페이지로 이동하면 사진·결과·픽셀 검사 값을 비웁니다. 브라우저 뒤로 가기가 BFCache에서 복귀해도 이전 개인 파일이나 진행을 되살리지 않고 시드 17의 첫 과제를 새로 시작합니다.

## 직접 실행

Node.js 22 이상. 앱 실행·단위 테스트·정적 검사에는 외부 패키지가 없습니다.

```sh
npm run dev -- 0
npm test
npm run check
```

첫 명령에 표시된 `http://127.0.0.1:포트/`를 엽니다. 로컬 서버는 정적 파일만 제공합니다. 업로드/API 처리 서버가 아닙니다.

짧은 확인 흐름:

1. 시드 17의 첫 과제에서 밝기 6으로 실행해 실패 설명과 차이 지도를 봅니다. 원본·목표 중앙 RGB의 차이 12를 확인한 뒤 밝기 12로 실행하면 MAE/RMSE 0이고 다음 과제가 열립니다.
2. 두 번째 과제에서 단서를 읽고 대칭 평균 커널을 구성합니다. `계수 합을 나누기로`로 평탄부 배율을 1로 맞춘 뒤 실행합니다. 지도 증폭 1×/16×를 바꿔도 점수는 같습니다.
3. 자유 처리 실험실에서 가우시안 → Sobel 크기 → 문턱값을 연결합니다. `오른쪽 결과`를 각 단계로 바꾸고 처리 순서에서 같은 단계를 눌러 실제 입력/출력을 검사합니다. 문턱값과 평균의 순서를 바꿔 결과가 달라지는지 봅니다.
4. 숫자를 지우거나 나누기를 0으로 실행하면 실패하고 PNG 저장이 비활성화됩니다. 유효 설정으로 다시 실행한 뒤 계산 취소·샘플 복원과 로컬 파일 가져오기/PNG 다운로드를 확인합니다.

선택적 브라우저 QA 스크립트는 [browser-smoke.js](tools/browser-smoke.js), [browser-limits.js](tools/browser-limits.js)입니다. 이미 설치/캐시된 Playwright CLI에서 로컬 URL을 연 뒤 다음처럼 실행합니다. 이 세션은 `--offline`으로 실행했습니다. 브라우저 설치나 원격 다운로드는 수행하지 않았습니다.

```sh
npx --offline --package @playwright/cli playwright-cli -s=pixel-kitchen-local open http://127.0.0.1:포트/ --headed
npx --offline --package @playwright/cli playwright-cli -s=pixel-kitchen-local run-code --filename tools/browser-smoke.js --raw
npx --offline --package @playwright/cli playwright-cli -s=pixel-kitchen-local run-code --filename tools/browser-limits.js --raw
```

QA 파일의 스크린샷 경로는 현재 앱의 절대 경로입니다. 다른 위치에서 실행하면 그 경로를 수정하세요. QA 산출물은 `output/playwright/`, CLI 임시 기록은 `.playwright-cli/`에 있으며 Git에서 제외하고 배포하지 않습니다.

## 계산·개인정보·자원 경계

순수 계산은 `dist/src/model.js`, 합성 과제/제약은 `dist/src/challenges.js`, DOM·파일·예약/취소는 `dist/src/app.js`에서 처리합니다. 백엔드·계정·쿠키·방문자 저장·추적·외부 사진·런타임 네트워크 호출이 없습니다. CSP는 `connect-src 'none'`을 유지합니다. 호스팅 자체의 로그는 앱 데이터 처리와 별개입니다. 사용자가 누르는 PNG 다운로드만 로컬 출력입니다. 선택적 WebMCP 요약에는 개인 사진 픽셀·파일명·과제 정답이 없습니다.

입력은 8 MiB 이하 PNG/JPEG/WebP, 디코딩 결과 24,000,000픽셀 이하, 계산 화면 720×480 이하입니다. 한 번에 디코더 하나만 허용하고 모든 완료 비트맵을 닫습니다. 사진 읽기 취소는 늦게 도착한 결과를 폐기하며 브라우저의 네이티브 디코더 자체를 강제 중단하지는 않습니다. 픽셀 수 검사는 디코딩 후이므로 디코딩 이전 메모리 상한 보장은 아닙니다.

파이프라인은 최대 4단계, 실행 전 40M work 예산을 검사하고 16행마다 UI에 제어를 돌려줍니다. work는 픽셀당 커널 27(+흑백 3), Sobel 57, 문턱값 6으로 계산하는 샘플/채널 평가 단위이며 실제 CPU 명령 수가 아닙니다. 중간 결과는 최대 4개입니다. 설정 변경·취소 후에는 이전 점수/결과를 지우며 완성된 현재 결과만 내보냅니다.

각 단계의 RGB는 0–255로 반올림·제한한 뒤 다음 단계에 입력하고, 알파는 유지합니다. 가장자리는 끝 픽셀 반복입니다. Rec.709 계수를 인코딩된 RGB 바이트에 적용하며 선형광/프리멀티플라이드 알파 합성을 구현하지 않습니다. 투명한 이웃의 저장 RGB도 계산에 포함됩니다. MAE/RMSE는 두 픽셀이 모두 완전 투명이 아닐 때의 RGB 바이트 비교이며 알파 오차는 별도 계산합니다. 차이 지도 증폭은 표시만 바꿉니다. 지각 품질을 검증한 통계나 손실된 세부 정보 복구를 주장하지 않습니다.

## 검증 상태 / 2026-10-09

- LOCAL: 독립 기준 계산기·수계산 예제·20개 시드/과제 조합·소수점 화면 배율 좌표를 포함한 17개 단위 테스트 통과. 정적 검사에는 구문·모듈 참조·CSP·계산/UI 경계·BOM/CRLF 확인이 포함됩니다.
- BROWSER_LOCAL: 로컬 Chromium에서 과제 진행, 실제 오차, 순서 실패, 와이프/검사기, 취소, 파일/알파/PNG 다운로드와 계산 예산을 확인했습니다. 320/390px는 데스크톱 브라우저의 화면 크기 모의 검사입니다.
- TEST_DOUBLE: 지연 디코딩 취소와 24MP 초과 치수 거절은 제어된 브라우저 테스트 대역입니다. 실제 25MP 파일 디코딩 검증과 구별합니다.
- NOT_RUN: 이번 변경의 원격 CI·공개 배포·라이브 URL 확인, 실제 모바일 기기 성능/터치, Firefox/WebKit, 지각 품질/사용자 연구.

정확한 실행 결과와 범위는 [검증 기록](docs/verification.md)에 기록합니다. [구조](architecture.md) · [결정 기록](docs/decisions.md). 기존 호스팅 워크플로는 보존했으나 이번 세션에서는 실행하지 않았습니다.
